How does one performed set retain all its meaning?

The set stores only its own measurements and foreign keys. Protected relationships supply movement, workout, gym, metric, machine, and load representation without update anomalies.

Planning

Safe to edit

`routines`, `movement_prescriptions`, and `prescribed_sets` describe the current plan. They never contain gym or machine data.

History

Protected from edits

Workout snapshot rows keep ordering, targets, instructions, names, movement references, and the selected effort metric.

Atomic record

Minimal set row

A performed set owns repetitions, load, optional effort, ordering, timestamp, and references. Context is retained through immutable paths.

Database-enforced invariants

  1. 1Routine, gym, movement, and workout ownership must resolve to the same trainee.
  2. 2A performed set's machine gym must equal its workout gym.
  3. 3Machine gym and load representation are immutable. Changes create a new machine.
  4. 4Workout source, gym, metric, and start time are immutable after creation.
  5. 5Plate-count load values are whole numbers and are never inferred as weight.

Extension seams

New prescription targets
Add typed child tables and matching snapshot tables, not JSON or EAV rows.
Machine calibration
Add a separate calibration policy. Never rewrite plate-count history.
Load comparison
Add explicit policy tables. Reporting remains partitioned by representation by default.
Backup and sync
Application-generated UUIDs or ULIDs keep identities portable.

One product rule still needs resolution

The ADRs do not define what happens to routine effort targets when the trainee switches between RPE and RIR. The safe default is to keep targets metric-qualified and require explicit re-authoring instead of silently converting or reinterpreting them.
